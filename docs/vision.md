# 📚 Class Homework Bot

> Telegram-бот для класса, который хранит расписание и домашние задания на прошлую, текущую и следующую неделю.

---

## 🎯 Идея

Бот хранит расписание класса и ДЗ по каждому уроку.

Любой ученик может:

- посмотреть расписание;
- посмотреть ДЗ на прошлую / текущую / следующую неделю;
- выбрать конкретный день и урок;
- записать новое ДЗ;
- посмотреть уже записанное ДЗ.

Основная задача — чтобы информация о домашке собиралась в одном месте и не дублировалась.

---

## 🧠 Основная логика

У бота есть три активные недели:

- **прошлая**;
- **текущая**;
- **следующая**.

Каждый урок имеет конкретную дату, предмет и номер урока.

ДЗ привязывается не просто к предмету, а к конкретному уроку конкретного дня.

Пример:

```text
07.09.2026
└── Понедельник
    ├── 1. Математика
    │   └── ДЗ: §12, №45–46
    ├── 2. Русский язык
    │   └── ДЗ: написать сочинение
    └── 3. Физика
        └── ДЗ: нет
```

---

# 🗄 Что хранит бот

## Lesson

Расписание конкретного урока.

```text
id
weekDate / date
day
lessonNumber
subject
```

Пример:

```text
2026-09-07
MONDAY
1
Математика
```

---

## Homework

Домашнее задание, привязанное к уроку.

```text
id
lessonId
text
createdBy     // опционально
createdAt
updatedAt
```

Пример:

```text
lessonId: 123
text: "Сделать №45–46, выучить правило §12"
```

---

## 📆 Почему хранить дату, а не просто "неделю №1"

Лучше привязывать уроки к конкретной дате.

Например:

```text
2026-09-07
2026-09-08
2026-09-09
...
```

Тогда бот сам понимает, какая неделя является:

```text
прошлой
текущей
следующей
```

И не нужно вручную переносить данные между неделями.

# 🤖 Сравнение домашнего задания

Главная задача AI — не создавать ДЗ, а определять, являются ли два текста одним и тем же заданием.

### Пример

Уже записано:

```text
Сделать упражнения 45 и 46, выучить правило.
```

Новый вариант:

```text
Упр. 45, 46 + выучить правило §12.
```

AI должен определить:

```json
{
  "same": true,
  "betterText": "Сделать упражнения 45–46 и выучить правило §12."
}
```

Если задания одинаковые — не создаём вторую запись.

Если новый вариант сформулирован лучше — можно заменить существующий текст.

Если задания разные — сохраняем новое ДЗ.

---

# 🧩 Логика сравнения

AI получает:

```text
Существующее ДЗ:
...

Новое ДЗ:
...
```

И отвечает структурированным результатом:

```text
same
betterText
```

### Важно

AI не является обязательной частью сохранения.

Если AI временно недоступен:

```text
новое ДЗ → статус PENDING → админ проверяет вручную
```

Бот продолжает работать без AI, но непроверенный текст никогда не
публикуется автоматически: админы получают уведомление с пометкой
«AI-проверка недоступна».

На первом этапе для такого маленького проекта достаточно простой LLM через OpenRouter.

Embeddings / vector database здесь не обязательны.

# 🕐 Работа недель

Бот постоянно работает с тремя неделями:

```text
[ Прошлая ] [ Текущая ] [ Следующая ]
```

Активный диапазон недель не хранится — он вычисляется от текущей даты
(`src/lib/weeks.ts`), поэтому переход недель происходит сам.

Логически получается:

```text
Было:
31.08 – 06.09  → прошлая
07.09 – 13.09  → текущая
14.09 – 20.09  → следующая

После обновления:

07.09 – 13.09  → прошлая
14.09 – 20.09  → текущая
21.09 – 27.09  → следующая
```

Старые записи лучше **не удалять физически**.

БД может хранить историю, а бот просто показывает нужные три недели.

Это практически ничего не стоит при размере данных одного класса.

# 📅 Расписание и ДЗ — разные сущности

Расписание существует независимо от домашнего задания.

```text
Lesson
└── subject
```

и отдельно:

```text
Homework
└── lessonId
└── text
```

Поэтому урок может существовать без ДЗ:

```text
Математика
└── ДЗ: нет
```

И позже к нему можно добавить ДЗ.

```text

```

```text
📚 Математика

```

# 🔐 Что делать с пользователями

На MVP отдельную систему аккаунтов можно не делать.

Telegram сам идентифицирует пользователя через `from.id`.

При необходимости позже можно добавить:

```text
User
├── telegramId
├── name
└── role
```

Например:

```text
STUDENT
ADMIN
```

Это пригодится, если позже понадобится разрешить только администратору менять расписание.

# 🔥 Главная идея проекта

```text
Расписание
    ↓
конкретный урок
    ↓
домашнее задание
    ↓
ученик добавляет информацию
    ↓
бот проверяет существующее ДЗ
    ↓
AI убирает дубли
    ↓
в классе всегда есть одно понятное ДЗ
```

Бот должен быть максимально простым для ученика:

> **Выбрал день → выбрал урок → записал ДЗ.**

А посмотреть информацию:

> **Выбрал неделю → выбрал день → получил ДЗ.**
